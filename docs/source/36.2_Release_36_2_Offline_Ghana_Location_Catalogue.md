# Release 36.2 — Offline Ghana Location Catalogue

## Production problem

Release 36.1 used proper dependent dropdowns, but the application still requested district and town data from an external directory while the user was filling the form. When that provider could not be reached from Railway, required registration and shop-settings fields displayed an unavailable message.

A required business-location field must not be blocked by a third-party outage.

## Correction

Release 36.2 moves Ghana district and town lookup into the application deployment:

- the 16-region list remains canonical application data
- a generated Ghana catalogue is committed under `src/data`
- `/api/ghana-locations` reads the bundled catalogue only
- the route performs no runtime external fetch
- registration, existing-shop settings and marketplace filters continue using the same dependent Region → District → Town flow
- suburb, street, building, landmark and other detailed address fields remain typed by the shopkeeper

## Catalogue generation

`scripts/generate-ghana-location-catalogue.mjs` converts a dated Ghana country snapshot into the compact application catalogue. It validates that all 16 regions are populated and refuses a snapshot with an obviously incomplete number of districts or populated places.

The committed Release 36.2 snapshot contains:

- 16 regions
- 265 source administrative district records before display normalisation
- 15,369 town, city and community records

Source administrative records can contain historical boundary names, suffix differences and spelling variants. The application deduplicates matching keys and applies reviewed display corrections for known variants. Future catalogue refreshes must be inspected before deployment rather than updated automatically in production.

## Reliability and safety

The user no longer needs the external Ghana directory to be online. The browser calls the EJM application itself, and the EJM route reads data that ships with the release.

No database migration is required. Existing shop locations are preserved, and no product, stock, order, payment, customer or tenant record is changed.

## Validation requirements

The permanent tests require:

- exactly 16 canonical regions
- a substantial bundled district and town catalogue
- no Ghana registry hostname or runtime `fetch` in the location API route
- native dependent dropdowns for Region, District and Town
- matching of saved names such as `Accra Metropolitan Assembly` and `Kumasi Metropolitan`
- complete lint, TypeScript, unit, tenant-isolation, production-build and Chromium acceptance success before merge
